# Portfolio project guidance

## Project

- This is Rodel Medina’s professional engineering portfolio.
- It is a buildless static site: `index.html`, `styles.css`, and `app.js`. There is no package manager, framework, or test suite. Do not add dependencies or a build system without a clear user request.
- `README.md` records the current content state. Keep it in sync when the implementation or content status changes.
- Treat this file as the shared source of truth for coding agents. `CLAUDE.md` imports it for Claude Code compatibility; do not duplicate these rules there.

## Product direction

- The site uses a conversation interface to make the portfolio easier to explore. It is a curated portfolio, not a live AI assistant. Never imply that the visitor’s question is answered by a model or backend service.
- Keep the layout clear and professional, with the ease of a mobile app. Mobile responsiveness is a first-class requirement: preserve comfortable touch targets, safe-area spacing, readable type, an anchored composer, and usable navigation.
- Use white, black, and gray as the foundation, with restrained navy blue for interaction and focus. The site has light and dark themes; respect the system preference initially and remember a visitor’s explicit choice.
- The only brand mark is the "r." monogram: a drawn lowercase r with a blue dot on a rounded tile (dark tile in light mode, light tile in dark mode). It is defined once as inline SVG in `index.html` and as `markSvg` in `app.js`, and as `favicon.svg`. Do not add any other logo or brand graphic. Do not add a bubble background, generic AI hero, oversized marketing headline, decorative metrics, or filler sections. Keep motion subtle and honor `prefers-reduced-motion`.
- Keep SEO and accessibility intact: semantic HTML, one clear page `h1`, useful metadata, keyboard operation, visible focus, appropriate labels, sufficient contrast, and essential project information present in the initial HTML rather than only generated by JavaScript.

## Confidentiality and attribution

- Most work is client or employer work. Never add proprietary source code, confidential business information, internal screenshots, or unverified performance metrics.
- Attribute work accurately. Do not turn a partial contribution into sole ownership or claim unconfirmed architecture and results.
- Use sanitized explanations or original demonstrations when useful. Keep engagement attribution as recorded in `AGENTS.local.md` unless Rodel changes it.
- Distinguish confirmed details from placeholders in both UI copy and source content.

## Implementation conventions

- Keep the implementation simple and dependency-free unless the user explicitly changes the stack direction.
- Keep portfolio copy in the static HTML when it needs to be crawlable. JavaScript may provide progressive enhancement, curated chat responses, theme controls, and navigation, but must not present itself as a general-purpose AI.
- Keep interactions keyboard-accessible and announce meaningful dynamic responses without making the entire transcript noisy for screen readers.
- Preserve the current chat-inspired design, responsive drawer/composer, theme persistence, and reduced-motion behavior when changing nearby code.
- Do not replace or discard unrelated user changes. Inspect the affected files before editing.
- After implementation changes, use lightweight checks that fit the static site (for example, `node --check app.js`) and inspect the changed markup/styles. Do not invent npm commands; no `package.json` exists.

## Content workflow

- Rodel’s portfolio handoff and direct corrections are the content authority. Keep uncertain facts visibly provisional.
- Ask focused questions only when a missing detail blocks an accurate, useful case study. Continue work that does not depend on the answer.
- Before adding a new case study or a stronger claim, confirm the role, contribution, technologies, challenge, technical decisions, and what can be disclosed.
